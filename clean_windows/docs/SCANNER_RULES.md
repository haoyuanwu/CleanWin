# 清理规则整合

基于本机腾讯电脑管家 18.1 清理模块的静态分析，采用独立实现，仅加入经过范围约束的规则；不捆绑腾讯 DLL、原始脚本或整包规则库。

## 当前范围

- `cleanup_rules.dart`：明确的文件夹/文件名、扩展名、年龄、风险说明，以及用户/Windows 根目录类型。所有规则仍通过 ScanService 的白名单、链接检测、快照、去重和可操作性过滤。
- 快速软件缓存：VS Code/Insiders、Cursor、Windsurf、Discord、Slack、Spotify、Teams、钉钉、WPS 的特定可重建缓存；不遍历整个软件目录。
- 浏览器：保留原有 Chrome/Edge/Firefox 等，增加 QQ、360、搜狗、Yandex、百分浏览器的缓存根，支持嵌套用户配置。QQ 旧版 webkit_cache 单独识别。
- 用户系统缓存：旧版 IconCache.db、特定用户字体缓存文件、Roaming 证书下载缓存。纳入统一默认选择，不删除字体、证书和密钥。
- 显式日志检查：新增腾讯诊断日志、Framework/Framework64 的旧 .log、三十天前的 IIS 站点日志。日志未加入默认一键扫描，不清理 NativeImages、运行时和个人聊天数据。
- 下载：不再隐藏不足 10 MB 的项目；零字节文件也可审查。软件管家的已完成安装包逐文件展示，类型与修改时间筛选不再针对整个混合目录计算。
- 自定义下载目录：保留 Windows 重定向和腾讯/360 设置；增加已安装迅雷的 PrivateSpace/DefaultPath，以及 Chromium 系浏览器 Preferences 的 download.default_directory。

## 默认行为

概览候选默认自动勾选，显卡缓存除外。下载文件仍在独立页面手动选择，并通过现有确认流程移入回收站。回收站扫描会枚举当前用户在已就绪磁盘中的实际文件并汇总大小（包含已发现但正被占用的大小），清空前仍需确认。实际释放空间与移入回收站的体积继续分别统计。系统/安装根、用户根和 UNC 等过大的下载范围不接受；扫描不会运行任何下载包。

浏览器配置仅读取已知用户资料中的 Preferences，单文件至多 2 MiB；不读取历史、会话、密码数据库。损坏或无法访问的配置跳过。迅雷 INI 解析限制读取长度与行数，并兼容 BOM、UTF-8 和系统 ANSI 编码。目录发现失败仍保留其他已识别来源。

## 暂不纳入默认清理

内存转储已完全退出扫描、概览和清理范围，不再作为候选项显示。

.NET NativeImages、WinSxS/Installer、开发依赖、聊天记录和离线媒体，以及缺乏充分依据的 COM/ActiveX/共享 DLL/防火墙注册表项。不以腾讯规则中的推荐标记作为自动选择依据。

后续可独立增加卸载残留审查、离线媒体管理、开发缓存管理和扫描暂停/继续；这些不是本次已实现的功能。

## 验证

使用临时目录、注入环境和隔离 PowerShell 函数，验证快速扫描边界、白名单、占用过滤、小文件和零字节文件、混合下载包、多个浏览器配置、损坏/超限配置、时间过滤与日志边界。测试不扫描或清理真实用户文件。

## CPU 温度

腾讯硬件模块通过驱动和按 CPU 型号区分的硬件探测读取 CPU 温度；其 ACPI WMI 温区接口用于主板温度。项目已移除将该温区标成 CPU 温度的旧逻辑。

运行监控现在只接受已运行的 LibreHardwareMonitor/OpenHardwareMonitor CPU 传感器数据，优先包温并显示来源；读不到或来源失联时显示不可用，旧缓存不会冒充 CPU 温度。温度在后台读取，不阻塞进程列表。

本机只读检测未发现这两个提供者，因此当前没有真实 CPU 温度读数。此次没有安装或加载任何硬件驱动，也未调用腾讯私有设备接口。

## 微软空间清理与腾讯规则合并（2026-10-22）

详见 [REA 功能逻辑与合并对照](CLEANUP_MERGE_ANALYSIS.md)。概览共用统一空间扫描，扩展范围加入旧日志和痕迹审查，内存转储除外。增加系统待删除缓存、RDP 位图、CLR 日志、小组件网页/脚本缓存和 WebCache.old 窄规则；这些项目纳入统一默认选择。WER 收窄至七天前 ReportArchive/ReportQueue。专属窄规则拥有其范围，通用发现不得再扩大过滤范围。

系统更新和组件维护通过 Windows 磁盘清理入口操作，不直接删除数据库。重扫按分类替换，取消保留旧结果；缓存版本已更新。

## 软件缓存通用发现修复（2026-10-22）

快速扫描原来在少量固定规则后直接返回，导致其他已安装软件的缓存根本没有被检查。本次保留精确规则，并在 Local/Roaming/LocalLow 及空间扫描可访问的 ProgramData 中增加通用资源缓存和七天前诊断日志发现。常规目录深度 3，已知 User Data、LocalCache、Partitions 等用户配置容器最多再延伸 3 层；每个根最多检查 2000 个未排除目录，按广度优先覆盖不同软件，达到上限显示提示，可启用深度扫描继续。

补入 WorkBuddy、Trae、优酷、哔哩哔哩的资源缓存，以及腾讯视频版本化 WebView 用户配置路径。专属窄规则继续拥有其范围，通用发现不扩大过滤。程序依赖、模型、聊天日志/文件、会话存储、离线视频与隔离区不会作为常规软件缓存发现。软件缓存分类在扫描完成后即使为空也保留检查提示；发现项默认勾选。

只读本机验证使用真实文件可操作性探测，不调用清理接口。不同软件把离线资源、依赖下载或正在使用的文件计入垃圾时，统计不会与腾讯的结果强行对齐。本次不改变权限和占用过滤。

最终本机只读核对：软件缓存分类发现 88 个缓存条目、41 组软件来源，共 793,107,006 字节（约 756 MiB），耗时约 5.7 秒；84 个占用/只读/权限不足文件跳过。发现范围触及 Local 目录元数据上限时会明确提示继续使用深度扫描。数值是验证时快照，不代表其他电脑或下一次扫描的结果。没有执行实际清理。


## 概览读取失败定位与修复（2026-10-22）

### 实测原因

- 快速通用软件缓存发现触及 2000 目录上限时，旧代码将提示混入“无法读取位置”数量。现在扫描范围提示与文件系统异常分别记录。
- 文件已枚举并统计后，旧代码仅返回可删除路径集合。占用、只读、系统属性、离线、重解析点、删除权限不足被统一合并；UI 又把所有 `error` 提示写成“部分位置未读取”。现在保留每个拒绝原因、Windows 错误码及分类内的真正读取失败数和不可清理文件数。
- 字体缓存原规则递归 `Windows/ServiceProfiles/LocalService/AppData/Local`，因此误入 Windows Hello 的 `Microsoft/Ngc`。改为根目录非递归、明确字体缓存文件名，以及单独 `FontCache` 目录。不遍历凭据与安全目录。
- 通用软件缓存发现原先也探测 ProgramData 下的 Windows 诊断、SmsRouter、系统包、加密和服务状态存储区。现在通用发现排除这些系统服务数据，明确系统规则仍只处理自己支持的窄目录。

### 腾讯管家差异的本机证据

只读服务查询确认 `qmbsrv`、`QQPCRTP` 运行账户为 LocalSystem。管理员只读扫描剩余的 `C:/ProgramData/Windows Master Store/ServiceData`，其 ACL 所有者为 SYSTEM，允许项仅有 SYSTEM 与 `NT SERVICE/PCManager Service Store`，没有 Administrators。因此单纯提高到管理员不等于具有该目录的枚举权限。该目录是服务私有数据，不属于通用软件缓存规则，已加入精确排除边界；不更改它的 ACL 或所有权。

这份证据只说明账户与访问控制差异，不证明腾讯的每一个扫描目标都由哪个服务执行，也不证明其能读取所有目录。官方机制见 [Windows LocalSystem](https://learn.microsoft.com/en-us/windows/win32/services/localsystem-account)、[文件访问控制](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)。

### 展示与清理

分类显示具体状态：真正读取失败显示未读取位置数；已统计而不能清理显示不可清理文件数；只有范围/策略提示时显示扫描提示。展开后保留路径、错误码和原因，并可选择文本或复制诊断。诊断计数随分类缓存保存，重扫更新。

可清理权限核对仍使用无修改的独占 DELETE 探测，不结束相关软件，不扩大默认勾选，不强制删除受保护文件。读取失败、删除失败和扫描范围限制互相独立。只有符合既有文件类型、年龄、路径与权限规则的快照才参与清理。

验证包含真实只读管理员扫描、原生文件占用/只读/消失测试、字体目录边界、服务区排除边界、分类标签和诊断复制。实际扫描只读取元数据，不执行清理；统计是当时快照，不代表电脑管家的同口径结果。


最终管理员只读核对覆盖概览当前八类（缓存、转储、日志、回收站、痕迹），完整完成耗时约 17.6 秒，各类真正读取失败数均为 0。占用或属性保护的文件单独显示为不可清理，快速发现上限仍单独提示；这是本机该次快照，不表示任何目录都能访问。

扫描缓存键升级为 `results_v9_access_bounds`，旧范围的候选清单不再恢复，需要按新边界重新扫描；白名单和偏好不变。


## 系统组件清理（2026-10-22，2026-10-23 调整入口）

概览与清理不再区分“普通/深度”，也不再提供独立弹窗；常规垃圾统一使用
`AppState.scanSpaceCleanup` 的扫描结果、白名单、逐项选择及既有清理确认流程。
Windows 组件维护作为同一页面内的“系统组件”区块展示，由 app-owned
`SystemCleanupController` 管理，切换模块后保持进度，任务中心显示后台状态。

- 只读分析：受信任系统目录的 DISM.exe，/English /Online /Cleanup-Image /AnalyzeComponentStore /NoRestart。
- 分析输出需同时识别可回收包数与系统建议；仅建议清理且包数大于 0 时允许用户二次确认。分析 30 分钟后需重新分析。
- 维护：/StartComponentCleanup /NoRestart；不使用 ResetBase 或 SPSuperseded，不枚举删除 WinSxS 文件，不自动重启。
- 常规扫描/删除与系统维护互斥，避免系统日志、缓存被并发访问；分析支持取消，组件维护不强杀，切换模块后后台继续。
- 退出码 0 为成功，3010 为成功但需用户择时重启，其余均显示失败。无法识别的分析输出不能用于开启清理。
- 不把组件存储总大小或包数计入可释放空间，不伪报“已释放 0 B”。系统维护独立显示完成反馈与可复制诊断。
- 测试使用模拟 runner 验证确认、取消、失败、重启提示及 560/1000 宽度；本机实际只执行只读 AnalyzeComponentStore 验证，不执行维护清理。

参考：[组件清理](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/clean-up-the-winsxs-folder?view=windows-11)、[组件存储分析](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/determine-the-actual-size-of-the-winsxs-folder?view=windows-11)。

本机只读集成验证：DISM 退出码 0，正确解析 5 个可回收包及 Recommended: Yes；本次未执行实际组件清理。全量回归 235 项通过、4 项可选预览跳过；后续新增任务中心互斥验证 6 项通过，发布构建及 Inno 安装包生成成功。


## 被占用文件的统计与软件恢复（2026-10-23）

修正“无法删除就不统计”的耦合：已成功取得大小和时间的候选文件即使独占删除探测失败，仍保留其观测字节数和文件数。CleanItem.sizeBytes/scannedFiles/fileSignatures 仅包含可清理文件；blockedSizeBytes/blockedFileCount 只用于统计。首页分类/条目显示已发现总量，同时说明可清理与暂不可清理大小；选择金额只计可操作文件。全被占用的条目不能勾选；清完可操作部分后保留占用统计，解锁重扫后重新确认。白名单及链接过滤仍在统计前生效，消失文件不计入新统计；不能读取元数据的文件仍提示读取失败。

占用处理使用 Windows Restart Manager。首次扫描发现共享冲突后，界面列出占用软件；用户可逐项选择或一键选择全部可安全恢复的普通应用。CleanWin 只请求正常退出，不强制结束无响应程序，不处理系统关键进程、服务、资源管理器或 Restart Manager 无法恢复的软件。所选应用退出后重新扫描，并在扫描完成后恢复。清理前重新探测并再次询问；拒绝时只跳过仍被占用的文件，允许时只关闭本次选择的软件，清理结束后恢复。扫描缓存键升级为 `results_v11_occupied_apps`，避免把旧快照当成可恢复占用清单。

立即加速只扫描用户 Temp 与 Windows/Temp 七天前的 tmp/temp。临时扫描复用原扫描/权限/白名单及签名核对，保留其他系统缓存和选择；清理通过明确 itemIds 限定，不能把此前选中的字体、图标或其他缓存一起清理。
