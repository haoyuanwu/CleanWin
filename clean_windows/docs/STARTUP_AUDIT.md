# 启动项扫描补全

## 已修复的问题

- 旧版按「位置标签＋名称」去重，Run、RunOnce、不同注册表视图中的同名项目会丢失。
  新版按实际键、32/64 位视图、值名、文件或任务完整路径区分。
- RunOnce 被错误当作 Run 操作。现在记录精确原始位置，修改前核对原命令和数据类型。
- 旧版把注册表值名加 `.disabled`，Windows 仍可能执行该值。现在将数据转存到
  原键下不参与自动执行的 `CleanWinDisabled` 子键，再移除原值；恢复时禁止覆盖同名值。
  旧的 `.disabled` 值仍处于可执行键中，会按实际情况列出，不擅自改动。
- 所有命令、名称和路径使用 Base64 JSON 传参，避免引号等特殊字符改变脚本含义。
- 刷新过程中保留已有结果，失败不清空；扫描部分失败时显示未读取来源。

## 扫描范围

| 来源 | 覆盖范围 | 操作 |
| --- | --- | --- |
| 注册表 | 当前用户、所有用户的 32/64 位 Run、RunOnce | 普通项可禁用和恢复 |
| 策略 | 两个用户范围、两个视图的 Policies/Explorer/Run | 只读 |
| 启动文件夹 | 系统 API 返回的当前用户和公共启动文件夹，含隐藏文件；排除 desktop.ini | 禁用、恢复、确认后删除 |
| 计划任务 | 遍历任务子目录及隐藏任务，列出含登录或开机触发器的任务 | 只读 |
| 自动服务 | Win32_Service 中自动启动的服务，显示延迟启动与当前运行状态 | 只读 |
| 商店应用 | 当前用户应用清单中的 windows.startupTask 声明 | 只读，不推测实际启用状态 |
| 系统登录 | HKLM Winlogon 的 Shell、Userinit | 只读 |

启动文件夹使用系统已知文件夹 API，支持重定向路径；快捷方式读取目标和参数，
同时保留原链接路径。文件操作只允许直接位于对应启动文件夹中的文件。
注册表禁用保留 REG_SZ/REG_EXPAND_SZ 类型和未展开的环境变量。
写入备份成功后才移除原值，删除原值失败会尝试撤回备份；不覆盖已有数据。

会读取 StartupApproved 的常见状态，与 Windows 禁用状态冲突的项目提供只读展示。
无法识别或读取状态时显示未确认，不默认认定为已启用。该数据结构不是稳定的公共 API，
本项目不写入它；应通过 Windows 启动应用设置调整由 Windows 禁用的项目。

## 界面与限制

新增来源筛选和数量，保留名称/完整命令/来源/发布者查找与启用状态筛选。
点击条目查看完整信息，可选择复制。未确认状态不计入“已启用/已禁用”。
系统类项目不会提供直接切换开关，防止在普通启动管理中误改系统组件。

这不是全系统 Autoruns：不扫描其他用户的未加载注册表、驱动、WMI 持久订阅、
Active Setup、RunOnceEx、全部组策略登录脚本及扩展加载机制。
只读扫描无须先授权；无法读取的来源会提示，管理员身份也不保证读取全部受保护位置。

## 验证

在本机只读核对发现 166 项：注册表 14、计划任务 44、自动服务 94、商店声明 8、
系统登录 2；此数量是验证时的结果，随安装软件与系统配置变化。
测试覆盖同名项区分、缓存与部分失败、只读限制、精确修改目标、特殊字符编码、
脚本语法、来源筛选、未知状态及刷新保留结果。
测试没有实际修改任何系统启动项，启用/禁用操作仍需在受控 Windows 环境交互验收。
